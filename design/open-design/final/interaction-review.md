# 翻盘棋 · 交互检查与修订

在视觉与规则不变的前提下，逐屏检查了首页、模式选择、对局、好友房、加入房间、结算、棋谱、章节与浮层。下面按“用户能感知到的影响”记录四轮改动、原因，以及有意保留的部分。

## 第四轮：按微信小程序的手势与骨架重排

### 1. 顶栏不像小程序

**现象**：品牌字标、声音按钮和返回键挤在一行，标题长度随页面变化左右跳动；在手机上既不像原生导航，也没有小程序右上角的胶囊。

**处理**：顶部拆成 44px 状态栏和 44px 标题栏。状态栏在桌面演示时显示 9:41 与信号，真机交给系统并让出安全区；标题栏固定「返回 / 17px 居中标题 / 胶囊」三列，胶囊内是「更多」与「收起」。声音按钮从顶栏移除，统一收进「更多 → 设置与偏好」和对局工具栏，避免两个入口的状态不同步。

### 2. 底栏只有首页能用

**现象**：底栏只在棋桌首页出现，棋谱与章节必须从首页卡片进入，再靠返回键退出；进入对局后底栏消失，层级关系不固定。

**处理**：底栏改为三项 tabBar：棋桌 / 棋谱 / 章节，图标在上、10px 标签在下，当前项深绿。三个主页面常驻 tabBar；模式、对局、房间、加入、结算等任务页隐藏 tabBar，只留返回键，避免误触离开棋局。

### 3. 页面切换没有方向

**处理**：为页面标注层级（tab 根 0、模式 1、对局 / 房间 / 加入 2、结算 3），前进 push、返回 pop、tab 之间横移，动画 280–300ms，只作用于当前页。返回键、Esc 和左缘 26px 起手、横向超过 72px 的右滑都走同一条 `confirmBack`，原有的暂停与收起棋桌确认全部保留。

### 4. 所有浮层长得一样

**现象**：认输、离开棋桌、更多菜单和规则说明都用同一种底部浮层，确认动作藏在正文按钮里，和微信里“对话框 / 操作表 / 半屏”的分工不一致。

**处理**：浮层分三种。规则、技能、回放、设置仍是可下拉关闭的底部浮层；认输、收起小程序、离开棋桌、替换当前棋局改为居中 300px 对话框，左右双按钮，危险操作用朱砂；胶囊「更多」改为底部 action sheet，56px 行高，设置与偏好 / 对弈规则 / 回到棋桌，加一颗独立取消。对话框与 action sheet 隐藏标准标题栏，用 `aria-label` 保留可访问名称，焦点落在第一个按钮，Esc 与遮罩仍可关闭，退场与焦点归还沿用同一套逻辑。

### 5. 提示与控件尺寸不像原生

**处理**：轻提示从底部条移到屏幕中央的深色小圆角块，停留 2.4 秒；按钮改为 48px 高、8px 圆角，主按钮深绿、次按钮纸面；列表行 44–56px，设置开关 46 × 28，棋谱行补 16px 右箭头，章节的「进入」箭头也统一为 chevron。

### 6. 渲染后发现两处骨架错位

- 返回键在 tab 根页隐藏后，标题成为 grid 的第一个可见子项，落进 92px 的第一列，胶囊也随之内缩，标题贴左而不是居中。给返回、标题、胶囊分别指定 `grid-column:1 / 2 / 3`，布局不再依赖可见元素数量。
- 状态栏只画出信号图标且停在中线：外层 `svg` 没有 `viewBox`，又用 `width:auto`，Chrome 得不到固有比例。改为 14 / 16 / 24px 的显式宽度，三个图标右对齐。

### 7. 底栏与胶囊点下去没有手感

**现象**：tabBar 和胶囊只有颜色变化，点按时图标完全静止；在触屏上不容易确认这一下是否点中，也不像微信里带轻反馈的原生控件。

**处理**：tabBar 图标被点中时上浮 2px、放大到 1.14 再回弹，选中项描边由 1.7 加到 2；胶囊「更多」的三点左右轻推，「收起」的圆点收拢并回转。两者同时给 8ms 轻振动，沿用「轻触振动」开关并改为默认开启；关闭动效或系统「减少动态效果」时不播放动画，但保留振动。按下瞬间另有 scale(.84–.86) 的按压态，松开后才触发页面切换。

### 8. 棋局里的控制没有触感

**现象**：落子格按下只有底色变化，悔棋、技能选择与发动完全没有按压态，也不振动；和刚补过的 tabBar、胶囊不是一套手感。

**处理**：合法落子格按下时把黄铜光点放大成当前手方的棋子预览，抬手给 8ms 轻振；这一手的落子音效不再重复 12ms，保证一次操作只振一次。AI 与好友的落子仍保留 12ms，爆破仍保留 [15, 35, 20] 的节奏。悔棋、技能选择、技能详情、装配与发动都补上 200ms 的 scale 回弹和 8ms 轻振，禁用的悔棋不触发；关闭动效只停回弹，关闭振动才彻底安静。

## 第三轮：把棋谱还原成棋盘

### 1. 结算页只有落子列表

**现象**：一局结束后能读到“黑 D3、翻 2 子”，却看不到那一手落下前的棋盘。想复盘“哪一手翻了盘”，只能凭记忆。

**处理**：结算页的「回看棋谱」改成「逐手回看」，打开一个回放浮层：上方是棋盘，中间是手数与比分，下面是进度滑块、四个步进按钮和落子记录。默认停在终局，往回拨即可看到每一手之前的局面。

### 2. 回放不存 40 份棋盘

**处理**：记录里已经有每手的落点、翻子与爆破额外翻转，打开回放时从标准开局按序重算，得到 N + 1 个局面。每局只多一次临时计算，不把 40 份 64 格数组写进本地存储。

### 3. 键盘、触屏与读屏

- 滑块、四个按钮、左右（上下）方向键、Home / End 都能换手；焦点在滑块上时交给浏览器原生步进，避免一次按键走两格。
- 棋盘带 `role="img"`，标签随局面更新为“第 N 手后的棋盘，黑棋 X 子，白棋 Y 子”；手数与比分放在 `aria-live` 行里，换手时读屏只播报这一行。
- 落子记录每行 44px 高、可点击跳转，但不进入 Tab 顺序（`tabindex="-1"`）：回放的主路径是滑块和四个按钮，避免 Tab 穿过四十行。
- 到开局或终局时，越界的按钮用 `aria-disabled` 而不是 `disabled`，焦点不会被夺走；再点也只是停在边界。

### 4. 小屏与浮层高度

320 × 568 下浮层最多 511px 高，棋盘按 `max-height:680px` 收到 212px，其余内容在浮层内滚动；390 × 844 下棋盘 288px，整块不用滚动就能看全。浮层沿用固定标题栏与独立滚动正文。

### 5. 鼠标点击后关闭浮层，焦点回不到原按钮

**现象**：`openSheet` 用 `document.activeElement` 记录来源。Safari 点击按钮不会把焦点交给它，此时活动元素还是页面标题或 `body`，关闭浮层后焦点无处可回；这条路径在“逐手回看”上尤其明显。

**处理**：点击分发时把真正被点的按钮记为来源，`openSheet` 优先用它；嵌套浮层仍沿用第一次打开时的来源，不会被后一层覆盖。键盘 Enter 触发的点击走同一条路径。

## 第二轮：焦点、键盘与过渡

### 1. 换页之后，焦点留在上一页

**现象**：点“开始一局”或“棋谱”后，上一页整体隐藏，焦点随之落到 `body`。键盘用户要重新 Tab 穿过顶栏才能进入新页面；读屏也不会读出新的页面标题。

**处理**：换页后把焦点交给新页面的标题（`h1`，按需补 `tabindex="-1"`）；进入对局时直接落到棋盘上第一个可落子的格子，省掉三次 Tab。程序化聚焦不显示焦点框，但下一步 Tab 会从新页面的内容开始。

同时按页面记忆滚动位置：从棋谱打开一局再返回，回到原来的浏览位置，而不是被弹回顶部。

### 2. 棋谱 → 结算的返回路径

**现象**：从“我的棋谱”打开一局旧记录，结算页的返回键回到的是棋桌首页，而不是棋谱列表。

**处理**：记录下打开来源，返回键（以及 Esc）回到棋谱，并恢复之前的滚动位置。对局结束后的结算页仍然回首页，因为它没有“上一页”可说；从记录点“再来一局”会清掉这个来源，避免新对局结束后误回棋谱。

### 3. 方向键会跳行

**现象**：棋盘用 roving tabindex 支持方向键，但步进是按一维下标 `±1 / ±8` 算的。在 H 列按右方向键，会落到下一行的 A 列，视觉上像是焦点凭空跳走。

**处理**：改为按行列推进，只在同一行或同一列里找下一个合法格；到边界就停住，不再换行。

### 4. 三组单选项只是“按钮组”

**现象**：对局模式、对手强度、棋局规则都是 `aria-pressed` 的按钮，读屏会读成三个独立开关；键盘要 Tab 三次才能过一组，方向键也不能切换。

**处理**：改成真正的 `radiogroup` / `radio` / `aria-checked`，每组只有一个 Tab 停靠点，左右（上下）方向键切换选项并同步焦点。视觉状态改用 `aria-checked` 驱动，原来的 `aria-pressed` 样式一并移除。

### 5. 浮层退场的 190ms 死区

**现象**：浮层关闭有 180ms 的淡出，但遮罩在这段时间里仍然拦截点击，键盘也仍被当成“浮层打开”。于是从浮层里点“确认认输”“离开棋桌”跳到新页面后，紧接着的一次点击或输入会被吃掉；关闭动效时更明显，因为画面已经瞬时消失，输入却还在等计时器。

**处理**：退场中的遮罩加 `pointer-events:none`，并把 `is-closing` 视为“已关闭”——点击、数字键、Esc 都不再被拦。关闭动效关闭时直接跳过 180ms，立即完成。

### 6. 每 3 秒重复写一遍同样的字

**现象**：好友房靠 3 秒心跳刷新。每次刷新都会重写房间状态、邀请按钮的 `innerHTML` 和玩家名；房间状态是 `aria-live`，读屏会在等候时反复念“等待好友加入…”。对局的回合文案与落子反馈也有同样的问题。

**处理**：新增 `setText` / `setHTML`，值没变就不写 DOM；邀请按钮的文案先算好再比对。心跳现在只更新时间，房间状态、邀请按钮、玩家名与能量格都不会被重复写一遍。

### 7. 落点只有一个小铜点

**现象**：合法格只有 15% 的铜色圆点，看不出“落下去会是什么颜色”，尤其在同屏切磋换手之后。

**处理**：鼠标悬停或键盘聚焦合法格时，浮出一枚 72% 大小的本方棋子虚影，铜点同时淡出；触屏不启用悬停虚影。棋色跟着当前手方走，`#board[data-turn]` 负责切换。

### 8. 锁住的章节点不动也不解释

**现象**：未解锁的章节用 `disabled`，不可聚焦、点了没反应；读屏只会跳过它。

**处理**：改用 `aria-disabled`，保留可聚焦；点下去会说明“完成上一章后，这一章会自然开启。”。视觉仍按未解锁处理。

### 9. 棋盘格的读屏标签只有棋色

**处理**：空格补“上一手”“建议落点”，合法格继续报“可落子，将翻转 N 子”。读屏现在能还原棋盘上的关键状态，而不只是黑白。

### 10. 悬停与底栏指示

- 分段控件和底栏的 hover 原本是把纸面提亮（`--surface`，只差 2–3 个亮度点），与上一轮修过的其他按钮不一致；改为同样的“纸面压深”`--hover`，触屏撤销。
- 底栏当前项原本在文字后加一个 3px 圆点，渲染出来像“棋桌 ·”的标点；改为文字下方的 18×2 短横线，读作 tab 指示而不是句号。
- 结算页的“复制本局回顾”补上与好友房一致的按钮态：复制成功后短暂显示“已复制，可粘贴”。

### 11. 极矮视口下棋盘会塌成一条线

**现象**：棋盘宽度按 `--phone-h - 353px` 计算。横屏手机（约 844 × 390）算出负值，被 0 或 26px 截断，棋盘几乎不可见。

**处理**：给棋盘宽度加 220px 下限，矮视口下宁可让对局页在手机内部纵向滚动，也不把棋盘压没。390 × 844 与 320 × 568 的构图不受影响。

## 第一轮：回合文案、焦点回位与浮层手感

### 1. 练习模式的回合文案会错位

独自练习时落子后，有约 700ms 的翻子动画窗口，回合栏显示“等待好友落子”。回合文案改为按模式判断——同屏显示“黑棋/白棋落子”，练习显示“轮到你落子/对手正在思考…”，好友房才使用“等待好友落子/连接暂停”。断线状态接到 `.status-dot.offline`。

### 2. 键盘落子后焦点掉回页面顶部

棋盘改为 roving tabindex；落子或 AI 应手后，焦点落到离上一手最近的合法格，方向键继续在合法格之间移动。只在键盘操作时回焦，鼠标落子不抢焦点，浮层打开时也不抢。

### 3. 浮层的三处手感问题

关闭从硬切改为 180ms 淡出 + 下沉；长内容改为“固定把手 + 固定标题栏 + 独立滚动正文”；把手与标题栏可下滑关闭，超过 90px 松手即关闭。关闭后焦点回到打开浮层的控件，Tab 在浮层内循环。

### 4. 加入房间页的键盘与重复提交

数字与退格在任何焦点位置都能输入，Enter 只提交一次；连接中禁用输入并保持“正在请房主开门…”；触屏把输入框设为只读，避免系统键盘顶起布局。

### 5. 暖纸上的悬停几乎看不见

新增 `--hover`（纸面压深），替换图标按钮、文字按钮、模式卡的浅色悬停；触屏撤销 hover。对比度：正文 9.8:1、次要文字 4.69:1。

### 6. 好友房的时限与复制反馈

邀请剩余时间按分钟更新；对局中改为“对局进行中 · 房间保持开放”；复制按钮 2.2 秒内显示“已复制，可粘贴”。

### 7. 从历史棋谱“再来一局”会用错模式

改为读取该条记录：练习局沿用难度与规则，同屏局保持同屏，好友房记录引导重新开桌，按钮文案随之区分。

### 8. 小的收口

模式卡过渡、棋盘与键盘禁选、`aria-haspopup="dialog"`、断线状态点同步。

## 保留项与原因

| 项目 | 现状 | 为什么这轮不动 |
| --- | --- | --- |
| 浏览器 / 安卓返回键 | 直接退出页面，不逐屏后退 | 页面内已有返回键、Esc 与左缘右滑，层级由 `SCREEN_DEPTH` 管理；宿主与浏览器返回键仍未接管 history，预览在 iframe 中容易与宿主路由冲突 |
| 后台标签页的心跳 | 好友房 3 秒发布一次，12 秒无更新判为暂停；后台节流可能误判 | 这是本地存储方案的固有限制，换成真实联机服务时一并解决 |
| 同屏切磋的战绩 | 按执黑一方计入胜场 | 与界面“黑棋 · 你”的现有设定一致，改动会改变统计口径，需产品确认 |
| 好友房的悔棋 | 按钮禁用，没有说明 | 禁用按钮不触发点击，`title` 在禁用态也常不显示；真要解释需要改成可点后再提示，属于规则层改动 |
| 浮层打开时 AI 继续落子 | 练习局会在浮层后应手 | 不计时的对局不会因此输棋，落子记录与音效仍在；若要做“暂停 AI”，需要新的对局状态 |
| 胶囊「收起」 | 原型内只给提示或确认 | 真正关闭小程序由微信宿主控制，原型不伪造退出 |
| 棋盘的语义结构 | `role="group"` + 64 个按钮 | 改成 grid/row/gridcell 需要重排 DOM 与焦点逻辑，当前按钮方案读屏可用 |

## 验证

- 两组 jsdom 桩共 79 项断言，执行真实事件路径：换页焦点与标题、单选组方向键、棋盘方向键不跨行、完整练习局（30 手真人 + 30 手 AI）到结算与存档、同屏悔棋、技能装配与消耗、好友房建房 / 入座 / 开局 / 双方落子、加入房间的数字键与退格、浮层开合与焦点归还、锁定章节提示。全部通过，无脚本异常。
- 没有引入新色值：分段控件与底栏的 hover 沿用了上一轮实测过的 `--hover`（正文 9.8:1、次要文字 4.69:1）；分段控件选中态仍为 `--fg` 底 + 象牙字；tabBar 选中态为深绿图标与标签，不使用下划线。焦点环保持 `--accent` 2px。
- 结构检查：86 个 `id` 无重复，无未处理的 `data-action`，无远程图片与字体请求，样式、脚本与括号配平；三种 `aria-*` 状态（checked / pressed / disabled）各归其位。
- 回放：300 局随机完整棋局（近 1.8 万手，含两千余次爆破额外翻转）逐手重建，第 k 手棋子总数恒为 4 + k，末态与实盘一致；脚本语法检查通过。
