# 翻盘棋 · uni-app 新前端

当前主前端位于 `uniapp/`，使用 **Vue 3 + TypeScript + uni-app（Vite）**，编译为 H5 和微信小程序。界面以本地 OpenDesign 最终稿为依据：暖纸、深绿棋桌、宋体标题、朱砂小印、黄铜能量，以及原稿中的棋桌图片和纸纹。

最终稿快照保存在 [`design/open-design/final/`](design/open-design/final/index.html)，含 `index.html`、`brand-spec.md`、`design-notes.md` 和 `interaction-review.md`。

## 运行新前端

使用 **Node.js >= 22.12.0**（当前 DCloud 编译器的要求）和 npm。DCloud 各包使用同一版本 `3.0.0-alpha-5030620261112001`，Vue 为 `3.4.21`，Vite 为 `5.2.8`，请按 lockfile 安装。

```bash
cd "/Volumes/T7 Mac/Development/vibe-reversi"
npm ci
npm run dev:h5
```

浏览器打开 **http://localhost:5173/**。开发服务器监听 `0.0.0.0:5173`，端口占用会直接报错；同一局域网设备可使用这台电脑的局域网 IP 和同一端口访问。

验证 H5 正式编译产物：

```bash
npm run build:h5
npm run preview:h5
```

打开 **http://localhost:4175/**。`preview:h5` 读取 `dist/build/h5/`，请先执行构建；改动源代码后需重新构建。`npm run dev` 等同于 `dev:h5`。

### 本机双窗口好友房

`dev:h5` 和 `preview:h5` 都注册了同源 `/api/friends` 服务，无需微信账号或云环境。

1. 在首页点「邀请好友」，或选择好友棋桌后创建房间，取得六位房号。
2. 使用「在另一窗口加入」模拟好友，或用隐私窗口、另一台设备打开邀请。普通同源标签页共享棋手身份，房主重开自己的邀请仍执黑。
3. 好友入座后，由房主开始。黑棋、白棋分别在自己的窗口落子，核对另一端棋盘、比分和回合同步；第三个独立窗口加入同一房间应被拒绝。
4. 可继续核对技能、认输、逐手回看、再来一局与离席。待加入邀请有效期为 10 分钟，对局中 90 秒未收到对方心跳会在后续同步时判定断线。

同一局要求两位棋手连接到**同一个房间服务进程／内存存储**；不同端口通常是独立进程，彼此看不到房间。`localhost` 与 `127.0.0.1` 在同一台电脑上可访问监听在相同端口的服务，但浏览器按 origin 隔离 `localStorage` 身份，切换地址会成为另一名本地棋手；局域网地址同理。实际邀请时应把同一个预览地址交给另一窗口。服务重启会清空房间；棋谱和偏好保存在当前浏览器。静态托管 `dist/build/h5/` 只提供页面，不含 `/api/friends` 后端，不能据此宣称生产 H5 好友房已交付。微信小程序使用独立的微信云服务，不能与这个本地 H5 房间互通。

## 新前端功能与规则

八个主界面为：棋桌首页、模式选择、进行中的棋局、好友棋桌、加入房间、结算棋谱、我的棋谱、章节练习。设置、技能列表与详情、规则、分享、确认和逐手回看通过浮层打开。三种对局方式为好友棋桌、独自练习、同屏切磋；独自练习有入门、进阶、高手三档难度，并可选择经典或技能规则。

新版导航在棋桌首页、我的棋谱、章节练习显示「棋桌／棋谱／章节」三项底栏，其余页面使用居中标题与返回按钮。回看、邀请、设置和确认操作都使用带阴影的居中弹框，周围保持透明。返回、Escape 与左边缘滑动共用退出确认逻辑。微信端保留系统胶囊，根页面的应用更多入口位于标题左侧。

微信小程序全局关闭界面动效和触感振动，页面、底栏和弹框即时切换。首页插画以 GIF 播放一次翻子，加载失败时显示静态图。音效开关和音量按设备保存。H5 的动效和振动可以分别在设置中调整，并遵从系统的减少动态效果偏好。

技能局双方初始 **3 点能量**，每次合法落子获得 1 点，最多 **6 点**。新前端使用原型的三项技能：

| 技能 | 消耗 | 规则 |
| --- | --- | --- |
| 十字爆破 | 3 | 正常落子并翻子后，额外翻转落点上下左右紧邻的敌子；可重复使用 |
| 洞察一步 | 2 | 标记一个建议合法落点，每回合至多一次，不代替落子 |
| 蓄势一手 | 0 | 下一次落子额外获得 2 点能量，仍受 6 点上限约束；每位棋手每局一次 |

经典局使用标准八方向夹子规则，无处落子时自动让手，双方无落点即结束。三章练习依次为「初识翻转」「守住四角」「终盘有数」，各对应一档经典人机练习，完成一局后解锁下一章。真实完成的对局可以保存棋谱并逐手回看。

## 微信小程序构建与导入

先生成无需真实微信配置的本地工程：

```bash
npm run build:mp-weixin
```

在微信开发者工具中导入 **`dist/build/mp-weixin/`**，工程类型为**小程序**。未配置 AppID 时，构建使用 `touristappid`。微信云联机和真机预览使用 `.env.local` 配置的真实 AppID 和云环境。

需要边改边编译时：

```bash
npm run dev:mp-weixin
```

保持命令运行，在开发者工具导入 **`dist/dev/mp-weixin/`**。等首次编译成功后再导入；后续客户端和云函数规则变化都会更新输出。微信小程序的运行容器是微信开发者工具／微信，`preview:h5` 只用于 H5。

### 配置自己的 AppID 和云环境

```bash
cp .env.wechat.example .env.local
```

编辑 `.env.local` 中的 `WECHAT_APPID` 和 `WECHAT_CLOUD_ENV`，分别填写项目自己的真实小程序 AppID、绑定该 AppID 的微信云开发环境 ID，然后重新执行构建。两个变量留空仍可编译。不要在 `manifest.json` 中填写 `${WECHAT_APPID}` 之类字符串占位符。

新构建脚本使用 Vite `loadEnv`，从仓库根的 env 文件读取 `WECHAT_` 前缀配置，并在启动 Vite 前传给子进程；优先级从高到低为：已导出的 shell 环境变量、`.env.[mode].local`、`.env.[mode]`、`.env.local`、`.env`。默认 dev 使用 `development`，build/preview 使用 `production`；可通过 `-- --mode staging` 指定其他模式。变量变化后要重启开发命令或重新构建，不能只刷新开发者工具。

真实 `.env` 文件已被 Git 忽略。AppID、云环境 ID 会写入最终产物，本身不是服务器密钥；不要在这些文件中放 AppSecret、私钥或 access token。脚本只报告是否缺少配置，不打印配置值。

### 小程序输出与云函数

```text
dist/build/mp-weixin/             # dev 命令对应 dist/dev/mp-weixin/
├── app.js / app.json / app.wxss
├── pages/、components/、common/、static/
├── project.config.json
└── cloudfunctions/
    └── reversiRoom/
        ├── index.js
        └── package.json
```

输出的 `project.config.json` 包含当前 AppID、`compileType: "miniprogram"`、`miniprogramRoot: "./"` 和 `cloudfunctionRoot: "cloudfunctions/"`。云函数目录通过 `packOptions.ignore` 排除在小程序客户端包之外。构建输出位于 `dist/dev/` 或 `dist/build/`。

云函数由 **`cloudfunctions/reversiRoom/index.ts` 直接打包**，包括共享的 `src/friends/game.ts`、`src/friends/rooms.ts` 与 legacy 分支；不复制可能过期的源目录 `index.js`。输出为 Node.js 18 兼容的 CommonJS，`wx-server-sdk` 保留外部依赖，由同目录 `package.json` 声明。

新小程序通过 `wx.cloud.callFunction({ name: 'reversiRoom', data: { action: 'friends', ... } })` 调用事务化房间服务，集合名为 **`friendRooms`**。真实跨设备联机前，需要项目所有者在开发者工具选择正确云环境，并对**本次新输出目录内**的 `reversiRoom` 执行「上传并部署：云端安装依赖」。集合由云函数尝试初始化；若环境权限不允许自动创建，需先在云开发控制台创建 `friendRooms`，客户端直接读写权限关闭，仅由云函数访问。旧 Canvas 分支使用的集合仍为 `rooms`／`users`。

微信端更换头像会把图片上传到当前云环境的 `avatars/` 目录，房间资料保存 `cloud://` 文件 ID。确保双方棋手可读取 `avatars/` 文件，写入权限限于文件创建者与管理员。上传失败时，新头像仅在本机预览，好友仍可看到上一次上传的头像。等待席位或头像读取失败时显示占位。

**这些构建命令不会部署云函数、生成真机二维码或上传开发版。** 配置 ID 也不代表云端已可用。真实微信验证应至少覆盖两位微信用户的建房、入座、房主开局、双方落子、非法操作拒绝、同步恢复、结算和再开局。

```bash
npm run typecheck:uniapp
npm run test:uniapp
npm run build:uniapp
```
